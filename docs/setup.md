# Adding shopify-ui to a Rails app

shopify-ui is a Rails engine packaged as the `shopify_ui` gem. Requirements: Rails 7+, Node 22+,
Yarn or npm.

## 1. Add the gem

`Gemfile`:

```ruby
gem "shopify_ui", git: "https://github.com/stackworx-co/Shopify-components.git", tag: "v1.0.0"
```

```bash
bundle install
```

That's all the Ruby setup: the engine autoloads the components under the `ShopifyUI` namespace,
so views can call `render ShopifyUI::ButtonComponent.new(...)`. `view_component` comes in as a
dependency.

## 2. Point Tailwind at the gem

The gem lives in Bundler's install directory, so its CSS path differs per machine. Generate a
small import file instead of hard-coding the path:

```bash
bin/rails shopify_ui:tailwind     # writes app/assets/stylesheets/shopify_ui.css
echo "/app/assets/stylesheets/shopify_ui.css" >> .gitignore
```

This also runs automatically before `assets:precompile` (and `tailwindcss:build`, if you use
tailwindcss-rails), so deploys always use the installed gem version.

## 3. Tailwind

```bash
yarn add -D tailwindcss@4.3.3 @tailwindcss/cli@4.3.3
```

`package.json` scripts:

```json
"build:tailwind": "bin/rails shopify_ui:tailwind && tailwindcss -i ./app/assets/stylesheets/tailwind.css -o ./app/assets/builds/tailwind.css --minify"
```

Also run it in production builds, e.g. add `&& yarn build:tailwind` to `heroku-postbuild`
(or `build`).

`app/assets/stylesheets/tailwind.css` (the app's entry file):

```css
/* tw: prefix + no Preflight + !important so it can sit next to Bootstrap or other CSS. */
@layer theme, base, components, utilities;
@import "tailwindcss/theme.css" layer(theme) prefix(tw);
@import "tailwindcss/utilities.css" layer(utilities) important;

@import "./shopify_ui.css";   /* generated by bin/rails shopify_ui:tailwind */

/* The app's own files that use tw: classes */
@source "../../views";
@source "../../components";
@source "../../helpers";
@source "../../javascript";
```

`theme.css` brings in the design tokens and tells Tailwind to scan shopify-ui's own components,
so their classes are generated in the app's build.

`Procfile.dev`:

```
tailwind: yarn build:tailwind --watch=always
```

Sprockets apps: `app/assets/builds` must be linked in `app/assets/config/manifest.js`
(`//= link_tree ../builds`), which is the default with cssbundling-rails.

## 4. Layout

In each layout that renders shopify-ui components, inside `<head>`:

```erb
<meta name="color-scheme" content="light">
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@450;550;650;700&display=swap">
<%= stylesheet_link_tag "tailwind", media: "all", "data-turbo-track": "reload" %>
```

Place the Tailwind stylesheet after the app's other stylesheets.

## 5. Node version (recommended)

`.nvmrc` in the app root:

```
22.11.0
```

## 6. Check it works

```bash
bin/rails runner 'puts ShopifyUI::VERSION'
yarn build:tailwind
```

The first prints the shopify-ui version; the second should finish without errors and
`app/assets/builds/tailwind.css` should contain the `--sui-*` tokens.

## Updating shopify-ui in an app

Change the `tag:` in the `Gemfile`, then:

```bash
bundle update shopify_ui
```

Each app pins its own tag, so apps upgrade independently.

## Local development against a checkout

To try unreleased component changes in an app without pushing:

```bash
bundle config set local.shopify_ui ~/projects/shopify-ui   # needs branch: "main" in the Gemfile line
# undo with: bundle config unset local.shopify_ui
```

## Alternative: Git submodule (no gem)

`git submodule add <repo-url> vendor/shopify-ui`, then in `config/application.rb`
`require_relative "../vendor/shopify-ui/lib/shopify_ui_setup"` and, inside the application class,
`ShopifyUISetup.configure(config)`. Import
`vendor/shopify-ui/app/assets/stylesheets/shopify_ui/theme.css` directly in the Tailwind entry.
